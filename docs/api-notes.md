# API — контракт известен, настоящий сервер не проверен

Источник: `data/source/Вставленный текст.txt`, Swagger «Регистратура» 1.0.0.
URL организаторов и токен отсутствуют. Никаких живых запросов/мутаций не выполнялось.

| Область | Подтверждённый текстом контракт |
|---|---|
| База / авторизация | /api/v1, Authorization: Bearer, токен команды |
| Даты | ДД.ММ.ГГГГ; дата-время ДД.ММ.ГГГГ ЧЧ:ММ; GMT+4, без offset |
| Врачи | GET /doctors, specialty exact без регистра; limit 1..50, offset; массив id/full_name/specialty/is_active |
| Клиенты | POST /clients: last_name, first_name, birth_date, optional middle_name/comment; 201 новый / 200 прежняя карточка |
| Поиск / карточка | GET /clients с фильтрами и пагинацией, GET /clients/{id}; PATCH только middle_name/comment |
| Создание визита | POST /visits: client_id int, doctor_id int, scheduled_at; 201 с id и Запланирована |
| Чтение визитов | GET /visits с client_id,doctor_id,status,date_from,date_to,limit,offset; GET /visits/{id} |
| Перенос / отмена | PATCH /visits/{id}: doctor_id/scheduled_at/status; статусы Запланирована, Отменена, Завершена. DELETE отсутствует |
| Эскалации | POST /escalations client_id/description, GET список и /{id}; неизменяемые; звонок не соединяют |

Терминальные записи не переносятся, изменение — 409; повторная отмена без изменения — 200.
Деактивированный врач не принимает новые записи; существующая допускает только отмену.
Клиенты, визиты, заявки изолированы по команде. GET чужого/отсутствующего объекта — одинаковый 404.
API НЕ хранит расписание, НЕ запрещает двойные слоты и НЕ показывает другие команды:
видимые API-записи не являются полной картиной занятости.

## Реализация и проверка

`core/api_simulator.py` — локальное исполнение документированных методов и ограничений;
`scripts/serve_mock_api.py` — только loopback HTTP. Источник врачей — Excel;
числовые ID 1001+ назначены **только симулятору**. Это не ID организаторов.
Тесты покрывают in-process контракт, настоящий локальный HTTP POST/PATCH/GET,
пагинацию, 400/401/404/409/429, а общий HTTP fixture — 5xx и timeout без повтора.
Тесты симулятора не сертифицируют полную совместимость с недоступным сервером:
машиночитаемый OpenAPI и реальные ответы ещё нужны для проверки всех крайних валидаций.

`SwaggerMIS` / `MISClient` / `RealMIS` используют тот же набор операций.
RealMIS требует MIS_BASE_URL/MIS_TOKEN, по умолчанию запрещает мутации;
реальная работа разрешается только явным owner_approved=True после отдельного согласования.
UI по умолчанию и фактически остаётся MOCK; автоматического переключения нет.

Excel Dxxx сопоставляется с API по нормализованным ФИО+специальности, неоднозначность
не угадывается; overrides проверяются отдельно. Справочник загружается страницами по 50 и кэшируется.
MOCK client IDs не используются в реальном POST: RealMIS выполняет точный поиск клиента.
Локальные брони имеют mis_mode, поэтому MOCK external_id не используется для LIVE PATCH.
Перед LIVE create проверяются активность врача и доступные своей команде записи.

Общий HTTP limiter — 8 попыток/скользящие 60 секунд для одного процесса, включая GET.
429 учитывает Retry-After; таймаут/5xx мутации → uncertain, без автоматического повтора.
При неопределённом переносе удерживаются оба времени; при отказе исходная бронь сохраняется.
Сверка с настоящим API после таймаута требует отдельной проверки перед любым новым действием.
Для нескольких процессов нужен общий межпроцессный limiter до включения LIVE.
