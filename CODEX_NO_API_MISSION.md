3. ВТОРОЕ: API-совместимый адаптер без сервера (P0)
Сейчас доступен текстовый контракт API, хотя сервер и токен отсутствуют. Не утверждать, что интеграция проверена. Реализовать:
- MISClient интерфейс/Protocol, MockMIS локально и RealMIS по HTTP, одинаковая семантика результатов (ok/rejected/uncertain). По умолчанию только MOCK, визуально отличимый в UI. MIS_MODE=live включается лишь при явном MIS_BASE_URL + MIS_TOKEN; без них запуск в live должен fail-closed.
- HTTP base path /api/v1, Bearer авторизация, дата ДД.ММ.ГГГГ, дата-время ДД.ММ.ГГГГ ЧЧ:ММ, часовой пояс стенда GMT+4 (НЕ локальная зона пользователя). Значение не содержит часовой offset.
- Точные задокументированные методы:
  - GET /doctors с specialty, limit, offset; ответ — массив объектов id (целое), full_name, specialty, is_active. limit максимум 50 — обязательная пагинация.
  - POST /clients с last_name, first_name, birth_date, опционально middle_name/comment: 201 новый, 200 уже существовал. GET /clients с фильтрами и пагинацией; GET /clients/{id}; PATCH /clients/{id} только отчество/комментарий.
  - POST /visits с {client_id: int, doctor_id: int, scheduled_at: 'ДД.ММ.ГГГГ ЧЧ:ММ'} → 201, внешний id и status: 'Запланирована'.
  - GET /visits с client_id, doctor_id, status, date_from, date_to, limit, offset; GET /visits/{id}.
  - PATCH /visits/{id} для изменения doctor_id, scheduled_at и/или status (Запланирована, Отменена, Завершена). Для переноса использовать PATCH, не выдумывать отдельный /reschedule или DELETE.
  - POST /escalations {client_id:int, description:str} → 201, GET /escalations / {id}. Запись эскалации НЕ означает реальный перевод звонка: сам стенд звонок не переводит.
- Очень важно: Excel IDs имеют вид D001, а API принимает числовые doctor_id. Сопоставить по нормализованному ФИО+специальности с API справочником при появлении доступа, ручная таблица override для неоднозначных совпадений. Не предполагать равенство этих идентификаторов.
- API не хранит расписания, не запрещает двойные слоты и не показывает записи других команд. Уникальность локального бронирования критична; видимый через API список не является исчерпывающим списком занятого времени.
- Централизованный лимитер <= 10 вызовов/мин всего (включая GET), консервативная цель 8/мин, поддержка 429 Retry-After, кэш справочника врачей, таймауты, протокол результата. Не повторять автоматически POST /visits после сетевого таймаута: uncertain, сверка через GET перед следующим действием.
- Реализовать мок-HTTP сервер (например FastAPI/TestClient/mock transport), который строго имитирует ответные коды, структуры, пагинацию, ошибку 409 для PATCH терминальных статусов, но НЕ объявлять его реальной МИС. Unit/integration-тесты на мок-HTTP, включая 400/401/404/409/429/500 и uncertain.
- Не выдавать новую карточку пациента с POST /clients за найденного реального пациента: создание синтетического клиента — отдельное явно подтверждённое действие. Не хранить реальные ПДн.

Документ РГ-ТЕЛ-01 является источником продуктовых правил, но если он противоречит реальной API-схеме, для формата вызова используем API, а для поведения робота — регламент.

- В речи: каждая реплика <= 20 слов, не более 3 вариантов, человек вправе сменить дату, время, врача или попросить оператора в любой момент. На втором непонимании предложить оператора, на третьем — эскалация.
- Критичные поля врач/дата/время/кабинет проговаривать и подтверждать; никогда не говорить «запись создана» до подтверждённого ответа хранилища / API.
- Красные флаги из раздела 7.4 проверяются до LLM на каждом ходе. Категория А — немедленная инструкция позвонить 103/112, отмена текущего сценария. Категория Б — оператор/неотложная помощь, вне часов регистратуры совет обратиться в 103 по регламенту. Жалобы — старшему администратору, медицина — не давать диагнозов/лекарств.
- Настоящий перевод по SIP пока отсутствует: UI должен честно показывать «Карточка передачи оператору сформирована (демо)», без ложного «звонок соединён». При наличии синтетического клиента поддержи мок записи /escalations.

- Unit-тесты handoff_phrases.csv >= 40 проверочных фраз, крайние случаи «боль» / «больница» / отрицание / прошедшие события / повторные уточнения.
